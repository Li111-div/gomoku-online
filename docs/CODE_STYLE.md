# 代码规范 · gomoku-p2p

> 适用于本项目 `index.html`、`styles/`、`js/` 下的全部代码。
> 规范的目标不是「好看」，而是让**六个月内回来看还能一眼读懂**、让 Review 有据可依。

---

## 0. 设计原则

1. **可离线运行优先** —— 不用 ES Module、不依赖构建工具、不引入外部 CDN。保证双击 `index.html` 就能跑起来，这是本项目最核心的约束。
2. **职责单一** —— 数据层不碰 DOM，渲染层不管网络，控制层只做编排。
3. **服务端权威** —— 棋局规则只允许存在于 `server/gomoku.py`。客户端 `js/` 下**不得出现任何胜负判断或落子校验**，它只负责「上报操作」与「渲染状态」。
4. **显式优于隐式** —— 全局能力集中在 `window.GM` 命名空间下，不污染 `window`。
5. **可读性优先于简洁** —— 注释解释「为什么」，代码本身说明「是什么」。

## 1. 目录与文件组织

```
gomoku-p2p/
├── index.html              4 个视图的静态结构
├── docs/                   规范与文档
├── server/                 服务端（Python，零依赖）
│   ├── server.py           入口：HTTP 托管 + WS 升级 + 消息路由
│   ├── ws.py               极简 WebSocket 实现
│   ├── gomoku.py           权威棋局逻辑（纯数据层）
│   ├── rooms.py            房间管理器（多对局隔离与生命周期）
│   └── protocol.py         消息类型常量
├── styles/
│   ├── theme.css           设计令牌 + 基础重置（不含组件样式）
│   ├── layout.css          页面骨架、视图容器、网格、响应式
│   └── components.css      可复用组件
└── js/                     客户端（浏览器）
    ├── config.js           常量与配置（无逻辑）
    ├── utils.js            无状态工具（DOM / 剪贴板 / 音效 / UI）
    ├── board.js            棋盘视图模型（**不含任何规则**）
    ├── renderer.js         渲染层
    ├── net.js              WebSocket 客户端 + 自动重连
    ├── views.js            路由
    └── app.js              控制器
```

**规则**

- 一个文件一个职责，文件名用小写单词，不加连字符或下划线。
- 加载顺序即依赖顺序：`config → utils → 领域层 → 网络 → 路由 → 控制器`。
- 全部使用普通 `<script>`，**禁止 `type="module"`** —— `file://` 协议下 ES Module 会被 CORS 拦截，页面直接白屏。
- 新增全局能力必须挂在 `window.GM` 下，禁止直接 `window.xxx = ...`。
- 不允许出现「模板残留」文件：任何一个文件都应该是被引用且被使用的。

## 2. 命名规范

| 对象 | 规范 | 示例 |
|---|---|---|
| 文件名 | 小写单词 | `renderer.js` |
| 全局命名空间 | `GM` + 大驼峰 | `GM.Game`、`GM.PeerLink` |
| 配置常量 | `GM.CONFIG` 下全大写蛇形 | `ICE_GATHER_TIMEOUT` |
| 消息类型 | `GM.MSG` 下全大写 | `MSG.SURRENDER` |
| 类 / 构造函数 | 大驼峰 | `Renderer`、`PeerLink` |
| 公开方法 | 小驼峰 | `App.init()` |
| 私有方法 / 字段 | 下划线前缀 | `_syncControls()`、`_reqTimer` |
| DOM id | 短横线 | `#msg-input`、`#btn-send-msg` |
| 自定义数据属性 | `data-` + 短横线 | `data-nav`、`data-mode` |
| CSS 类 | 短横线 + 语义 | `.chat-panel`、`.player-card` |
| CSS 状态类 | `is-` 前缀 | `.is-active`、`.is-me`、`.is-locked` |
| CSS 变量 | `--` + 语义 | `--surface`、`--accent`、`--r-md` |

**补充约定**

- 布尔变量/字段用 `is` / `has` / `can` / `should` 前缀：`_leaving`、`_canPlay()`、`canMsg`。
- 事件回调统一 `on` + 事件名：`onOpen`、`onMessage`、`_onChannelClose`。
- DOM 引用变量加 `El` 后缀或 `$` 前缀：`gameStatusEl`、`$board`。
- 坐标语义必须固定：`x` 为列（左→右），`y` 为行（上→下），`board[y][x]`。**任何地方都不得颠倒**。

## 3. JavaScript 规范

### 3.1 模块模式

每个文件用 IIFE 包裹，`'use strict'` 放在首行：

```js
/* ============================================================
   模块名 — 一句话说明职责
   ============================================================ */
(function (GM) {
  'use strict';

  const C = GM.CONFIG;      // 局部别名，减少属性链访问
  const MSG = GM.MSG;

  // ... 实现 ...

  GM.XxxName = XxxName;

})(window.GM = window.GM || {});
```

- 顶部用局部别名引用 `GM.CONFIG` / `GM.MSG`，避免在热路径上反复写 `GM.CONFIG.XXX`。
- 类统一用「构造函数 + prototype 对象字面量」，全项目保持一致，不混用 ES6 `class`。
- 函数统一用 `function` 声明 + `const self = this` 保存上下文。若某天要改用箭头函数，必须**整个文件一次性改完**，不允许两种风格混排。

### 3.2 注释规范

三级注释，各司其职：

**① 文件头** —— 写明文件名、职责，以及必要的领域约定：

```js
/* ============================================================
   game.js — 五子棋核心逻辑（纯数据层，不碰 DOM）
   棋盘坐标约定：x 为列（0..size-1，左→右）
                 y 为行（0..size-1，上→下）
   颜色：0 = 空，1 = 黑（先手），2 = 白（后手）
   ============================================================ */
```

**② 段落分隔** —— JS 用 `/* ============ 段落名 ============ */`，CSS 用 `/* ---------- 段落名 ---------- */`。

**③ 行内** —— 只写「为什么」，不写「做了什么」：

```js
/* 关键：无论这一步是否分出胜负，都如实把坐标发给对方，
   由双方各自在本地算出完全相同的结果 —— 从根上避免不同步 */
```

**必须写注释的场景**

- 反直觉的算法（`_trimLine` 的长连截取、`_syncGridHeight` 的等高策略）
- 兼容性 hack 及其原因
- 有意的取舍（「不强制拉到底部，避免打断用户翻看历史」）
- 对外协议字段含义

**禁止**：注释掉的死代码（直接删）、与代码不符的过时注释。

### 3.3 变量与常量

- 一律 `const`，需要重新赋值才用 `let`，**禁止 `var`**。
- 魔法数字必须提取到 `GM.CONFIG`：棋盘规格、超时时间、节流间隔、消息长度上限等。
- 常量表建议用 `Object.freeze` 包裹，防止被意外改写。
- 同一选择器使用两次以上就要缓存引用。

### 3.4 函数

- 单一职责，超过约 50 行考虑拆分。
- 参数超过 3 个改用对象传参。
- 用早返回（guard clause）替代深层 `if` 嵌套。
- 纯计算函数不产生副作用；有副作用的函数名要体现（`_applyMove`、`_syncControls`）。

### 3.5 异步

- 每个异步链**必须有 `.catch`**，不允许裸 `.then()`。
- 空 `catch {}` 必须写注释说明为什么可以安全忽略：

```js
try { this.link.dispose(); } catch (e) { /* 已释放，忽略 */ }
```

- 清理逻辑优先用 `.finally()`；若为兼容 ES5 风格而用 `.then()` 追加，需在注释中说明。
- 同一函数内不混用 `async/await` 与 `.then` 链。

### 3.6 DOM 与安全

- **禁止 `innerHTML` 拼接任何外部或用户输入**。用户数据一律走 `textContent` 或 `createElement`。
- `innerHTML = ''` 仅用于**清空容器**，属允许用法；更推荐的替代是 `replaceChildren()`。
- 拼接静态 SVG 字符串也应避免 —— 会丢失元素状态、破坏一致性。改用预置 HTML + `hidden` 切换，或用 `GM.el()` 构建。
- 所有渲染到页面的文本，来源无论是本地还是网络，一律按不可信处理。

### 3.7 事件与生命周期

- 事件绑定集中在 `_bindXxx()` 方法内，在 `init()` 中统一调用。
- **凡注册必须能注销**：`addEventListener`、`ResizeObserver`、`setInterval` 都要有对应移除路径。即使是单页应用，也要保留这个习惯。
- 全局监听（`window` / `document`）要格外谨慎，必须成对。
- 长按 / 拖拽判定用 Pointer Events，**不要同时绑 `click` + `touchend`**（移动端会重复触发）。
- 绑定在元素上的 `onclick = fn` 是覆盖式赋值，多个调用点会互相覆盖 —— 优先用 `addEventListener`。

### 3.8 错误处理

- 对外失败要有**用户可读**的提示（`GM.setStatus(..., 'err', ...)` 或 `GM.UI.toast`）。
- 网络 / 编解码错误必须带上原因，不能只显示「失败」。
- 失败路径要恢复按钮可用状态，不能把用户卡在禁用态。

## 4. CSS 规范

### 4.1 分层

| 文件 | 只放什么 | 禁止放什么 |
|---|---|---|
| `theme.css` | 设计令牌、主题、全局重置 | 任何组件样式 |
| `layout.css` | 页面骨架、视图容器、网格、断点 | 具体组件外观 |
| `components.css` | 按钮 / 卡片 / 面板 / 弹窗等可复用组件 | 一次性布局 |

### 4.2 设计令牌

- 颜色、圆角、阴影、动效**一律走 CSS 变量**，禁止硬编码色值（canvas 绘制与内联 SVG 图标除外）。
- 变量按**语义**命名（`--surface`、`--danger`），不按外观命名（`--gray-100`）。
- 新增变量必须同时补 `[data-theme="dark"]` 下的取值，否则暗色主题会缺色。

### 4.3 类名与状态

- 状态类统一 `is-` 前缀，用 `classList.toggle('is-x', cond)` 切换，**不要拼字符串**。
- 禁止用内联 `style` 表达设计意图；JS 动态计算的尺寸（如 `gridTemplateRows`）除外。
- JS 需要的状态放 `data-*` 属性，样式用属性选择器（如 `[data-color="1"]`）。

### 4.4 响应式

- 断点统一为三档，不得随意新增：

| 断点 | 布局 |
|---|---|
| `> 1040px` | 三栏：玩家栏 / 棋盘 / 侧栏 |
| `≤ 1040px` | 两栏：棋盘+侧栏，玩家栏移到下方 |
| `≤ 760px` | 单列：棋盘 → 玩家栏 → 侧栏 |
| `≤ 420px` | 微调字号与内边距 |

- 改动布局后必须验证：无横向滚动、无元素溢出、棋盘不被遮挡。
- 高度相关的布局（如三栏等高）优先用 JS 精确计算，不要指望纯 CSS 处理动态尺寸。

### 4.5 兼容性

- 使用较新特性必须提供降级：`color-mix()` 前补一行 `rgba()` fallback；`backdrop-filter` 带 `-webkit-` 前缀。
- 所有动效必须尊重 `prefers-reduced-motion`。

## 5. HTML 规范

- 语义化标签：`header` / `main` / `section` / `aside` / `ol` / `ul`。
- 每个视图是 `<section class="view" id="view-xxx">`，通过 `.is-active` 切换显隐。
- 交互元素一律用 `<button>`，**不要用 `<div onclick>`**。
- 图标统一内联 SVG，`viewBox="0 0 24 24"`，靠 `currentColor` 继承颜色；不使用图标字体或图片。
- 纯装饰性 SVG 加 `aria-hidden="true"`；纯图标按钮必须有 `aria-label`。
- 表单控件必须有 `<label>` 或 `aria-label`。

---

## 6. 网络协议规范

- 消息统一为 `{ t: 类型, ...payload }`。客户端常量在 `js/config.js` 的 `GM.MSG`，
  服务端常量在 `server/protocol.py`，**两边必须保持一致，改动时同步修改**。
- 新增消息类型必须同时完成三件事：① 在 `GM.MSG` 加常量；② 在 `_onMessage` 加分支；③ 在本文档补一行说明。
- 消息必须**幂等、可重放**：接收方对非法数据要安全拒绝，不能抛异常中断整个消息循环。
- 关键状态（棋局）必须能从消息流重建，并提供 `SYNC` 全量同步兜底。
- **接收方必须校验**：坐标范围、文本长度、字段类型。不要相信对方发来的任何数据。
- 服务端是唯一的规则裁判：客户端发来的任何操作都必须重新校验一遍，不能因为「界面上已经限制过」就跳过。
- 状态变化一律广播**完整快照**，不做增量推送 —— 客户端每次被完整覆盖，天然一致。

## 7. 性能规范

- 渲染统一走 `requestAnimationFrame` 批处理，禁止在事件回调里同步调用 `draw()`。
- **避免布局抖动**：先读后写，不要把 `getBoundingClientRect()` 夹在多次样式写入之间。
- 静态绘制内容（棋盘木纹等）应缓存到离屏 canvas，不要每帧重画。
- 高频回调（`pointermove`、`oniceconnectionstatechange`）要做节流，或遵循「值未变则不写 DOM」。
- 网络消息发送要节流（如 typing 提示 1.6s 一次）。
- 事件坐标换算必须考虑 CSS 缩放：`逻辑尺寸 / 显示尺寸`。
- 循环内不做重复 DOM 查询与重复计算。

## 8. 服务端（Python）规范

### 8.1 分层

| 文件 | 只放什么 | 禁止放什么 |
|---|---|---|
| `gomoku.py` | 棋局规则（纯数据层） | 网络、房间、JSON |
| `rooms.py` | 房间与会话管理、并发控制 | 棋局规则细节 |
| `ws.py` | WebSocket 协议 | 业务逻辑 |
| `server.py` | HTTP 路由、消息分发 | 直接改 `game` 对象 |
| `protocol.py` | 消息类型常量 | 任何逻辑 |

### 8.2 命名

- 模块、函数、变量：`snake_case`；类：`CamelCase`；常量：`UPPER_SNAKE`。
- 私有函数用 `_` 前缀：`_refresh_status`、`_push`。
- 消息处理函数统一 `on_<动作>`：`on_move`、`on_join`。

### 8.3 并发

- 共享可变状态必须有锁，且**锁顺序永远固定**（本项目：管理器 → 房间）。
- 持锁期间**不做 I/O**：广播时先在锁内取出目标列表，出锁后再发。
- 所有会改动棋局的操作必须收敛到 `Room` 的方法里（`apply_move` / `do_undo` / `do_reset`），
  外部不得直接读写 `room.game`。

### 8.4 健壮性

- 消息处理函数不得抛异常中断连接：入口统一 `try/except`，坏消息丢弃或回 `error`。
- 类型校验要显式：Python 里 `bool` 是 `int` 的子类，坐标校验必须排除 `True/False`。
- 客户端传来的数值一律做范围裁剪（棋盘规格 9–19、连子数 3–7、文本长度上限）。

### 8.5 依赖

- **只用标准库**。这是「双击即用」的前提，不要引入 `websockets` / `aiohttp` 等第三方包。

## 9. 提交规范

- 提交信息用「动词 + 范围 + 目的」：`修复对局界面三栏底部与棋盘对齐`。
- 一次提交只做一件事，重构与功能改动分开。
- 改动 UI 必须附截图或写明验证方式。
- 删除的代码不要留在注释里。
