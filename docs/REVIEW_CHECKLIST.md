# Code Review 检查清单 · gomoku-p2p

> 配套文档：[`CODE_REVIEW.md`](./CODE_REVIEW.md)（审查标准与流程，**先看这份**） · [`CODE_STYLE.md`](./CODE_STYLE.md)（代码规范）
> 本清单是流程中的 **L2 作者自查** 环节，提交审查前逐项过一遍。

## 使用方式

- **提交者**：提交前按 A → I 顺序逐项自查。
- **Reviewer**：只复核所有 🔴 项 + 本次改动涉及的 🟡 项，不做全量重读。
- 每项前面标 `[ ]`；通过标 `[x]`，不适用标 `[N/A]`。
- 🔴 = **必须项**，未通过不得合并；🟡 = 建议项，可记录为后续改进。

## A. 正确性

- [ ] 🔴 胜负判定覆盖横 / 竖 / 撇 / 捺四个方向，且只有连成 `WIN_COUNT` 子才判胜
- [ ] 🔴 长连（6 子及以上）处理正确，不越界、不误判、不截取错位置
- [ ] 🔴 棋盘填满时能正确判和棋
- [ ] 🔴 落子前三种校验齐全：越界、已有子、非本方回合
- [ ] 🔴 悔棋后 `turn` / `winner` / `winLine` / `ended` 全部正确回滚
- [ ] 🟡 序列化 → 反序列化往返后，棋局与原始状态逐字段一致
- [ ] 🟡 坐标语义未被颠倒（`x` 列 / `y` 行，`board[y][x]`）

## B. 状态与同步

- [ ] 🔴 **双方棋盘在任意时刻完全一致**，包括制胜那一手
- [ ] 🔴 胜负由双方**各自本地计算**，而非依赖对方告知结果
- [ ] 🔴 新增状态字段时，`reset()` / `serialize()` / `deserialize()` 三处同步更新
- [ ] 🔴 请求-应答类操作（重开 / 悔棋）双方状态机对称，不存在单边生效
- [ ] 🟡 消息丢失或错乱时有全量同步兜底
- [ ] 🟡 非法消息不会污染本地状态

## C. 网络与连接

- [ ] 🔴 客户端与服务端的消息类型常量保持一致（`js/config.js` ↔ `server/protocol.py`）
- [ ] 🔴 WebSocket 断开后自动重连，重连能恢复原席位与棋局
- [ ] 🔴 连接失败 / 异常断开有用户可见提示，不出现「界面卡住无反应」
- [ ] 🔴 服务端消息处理不因坏消息抛异常中断连接
- [ ] 🟡 发送消息前校验连接状态
- [ ] 🟡 重连采用退避策略，不做高频空转
- [ ] 🟡 切换房间时旧房间的席位已正确释放
- [ ] 🟡 心跳/超时机制能识别僵尸连接并回收

## D. 安全与健壮性

- [ ] 🔴 用户可控内容一律 `textContent`，**禁止 `innerHTML` 拼接**
- [ ] 🔴 服务端对客户端发来的每个操作都独立校验，不依赖客户端限制
- [ ] 🔴 接收到的消息做类型与长度校验（坐标范围、文本长度、字段类型）
- [ ] 🔴 消息处理对非法输入安全拒绝，不抛异常中断消息循环
- [ ] 🟡 对超大输入（粘贴的超长信令文本）有上限保护
- [ ] 🟡 不引入任何外部 CDN / 远程资源
- [ ] 🟡 不向 localStorage 写入敏感信息
- [ ] 🟡 有基本的消息频率约束，防止对端刷屏

## E. 性能

- [ ] 🔴 渲染走 `requestAnimationFrame` 批处理，无同步重绘
- [ ] 🔴 无布局抖动 —— 先读后写，`getBoundingClientRect()` 不夹在样式写入之间
- [ ] 🟡 静态绘制内容已缓存（棋盘木纹等），不每帧重画
- [ ] 🟡 高频回调有节流，或遵循「值未变则不写 DOM」
- [ ] 🟡 循环内无重复 DOM 查询、重复计算、重复对象构造
- [ ] 🟡 发送类网络消息有节流

## F. 内存与生命周期

- [ ] 🔴 `addEventListener` / `ResizeObserver` / 定时器都有对应注销路径
- [ ] 🔴 对象销毁时清理全部定时器（`clearTimeout` / `clearInterval`）
- [ ] 🔴 事件监听移除时使用同一函数引用（不能传匿名函数）
- [ ] 🟡 无声明后从未使用的字段 / 方法 / 变量
- [ ] 🟡 无注释掉的死代码
- [ ] 🟡 闭包未意外持有大对象或 DOM 引用

## G. UI / UX

- [ ] 🔴 按钮不可用时有 `disabled`，且样式可辨识
- [ ] 🔴 每个失败操作都有用户可读反馈，且**恢复按钮可用状态**
- [ ] 🔴 破坏性操作（认输 / 退出对局）有二次确认
- [ ] 🟡 异步操作有 loading 态，且防重复点击
- [ ] 🟡 空状态有提示文案
- [ ] 🟡 文案用词统一、无错别字

## H. 响应式与兼容性

- [ ] 🔴 `1040px` / `760px` / `420px` 三档断点下无横向滚动、无元素溢出
- [ ] 🔴 棋盘始终保持正方形，且不被其他元素遮挡
- [ ] 🔴 明暗双主题下文字对比度足够、无缺色
- [ ] 🟡 `color-mix()` / `backdrop-filter` 等新特性有降级写法
- [ ] 🟡 动效尊重 `prefers-reduced-motion`
- [ ] 🟡 触屏交互不依赖 hover

## I. 可维护性

- [ ] 🔴 遵循 `CODE_STYLE.md` 的命名与分层约定
- [ ] 🔴 非直觉逻辑有注释说明「为什么」
- [ ] 🔴 新增配置项进 `GM.CONFIG`，无魔法数字
- [ ] 🔴 新增消息类型已同步登记到 `GM.MSG` 与规范文档
- [ ] 🟡 新增 CSS 变量同时补了暗色主题取值
- [ ] 🟡 无「模板残留」式的未被引用文件

## 本项目问题与修复记录

> 2026-10-10 通读全部源码定位出 17 个问题，**当日已全部修复并回归验证**。

### 🟠 影响功能或性能（已修复）

| # | 位置 | 问题 | 修复方式 |
|---|---|---|---|
| 1 | `utils.js` `UI.dialog` | 全局只有一个 `#modal-host`，且遮罩用 `onclick = ...` **覆盖式赋值**。两个弹窗同时打开时（对手请求悔棋的弹窗还开着，用户又点了「认输」），第二个会顶掉第一个的按钮 —— **第一个 Promise 永远不 resolve**，对方的悔棋请求永远收不到回应 | 改为**弹窗队列**：`_queue` / `_active` / `_pump()` / `_settle()`，先入先出依次展示；遮罩改用 `addEventListener` 并在 `close()` 中 `removeEventListener` |
| 2 | `renderer.js` `_render` | 每帧重绘 **26 条木纹贝塞尔曲线**，纯静态内容却随每次落子、每次 hover 重画 | 新增 `_buildBackground()` 预渲染到离屏 canvas，以 `尺寸\|主题\|像素比` 为缓存键，绘制时 `drawImage` 复用 |
| 3 | `app.js` `_sendChat` / `_onMessage` | `CHAT_MAX_LENGTH: 60` 只在 HTML `maxlength` 生效，**JS 侧无校验**，对端可发超长文本撑爆气泡 | 发送与接收两侧都做 `.trim().slice(0, C.CHAT_MAX_LENGTH)`；空内容直接忽略 |
| 4 | `app.js` `_updateConn` → `_syncControls` | ICE 状态回调频繁触发，每次约 10 次 DOM 查询 + 写入 | 新增 `_buildNodeCache()` 缓存全部热路径节点，并提供 `_setText` / `_setClass` / `_setClassName` / `_setDisabled` 四个**值未变则不写**的写入器 |

## Review 流程

完整的审查标准与流程见 [`CODE_REVIEW.md`](./CODE_REVIEW.md)。这里只列出与本清单相关的部分：

1. **跑门禁** —— `python tools/preflight.py`，ERROR 必须为 0
2. **过本清单** —— 按 A → I 顺序逐项自查，🔴 必须项全部通过
3. **提交审查** —— 写清「改了什么 / 为什么改 / 怎么验证的」
4. **人工审查** —— 审查者按 P0–P3 分级，只审机器判断不了的部分
5. **端到端验证** —— 功能测试全绿后合入

> 清单里的 🔴 项对应 `CODE_REVIEW.md` 的 **P0/P1** 级别，
> 🟡 项对应 **P2** 级别 —— 即 🟡 项不阻塞合入，但应记入待办。


浏览器侧建议至少覆盖以下断言：

- 页面无 `pageerror` / `console.error`
- 四个视图可正常切换
- 多实例联机后**双方棋盘逐字节一致**（含制胜一子）
- **服务端权威性**：非本方回合 / 越界 / 已占 / 非法类型坐标一律被拒绝
- **本地状态篡改会被服务端广播覆盖**
- **多房间并行互不干扰**
- 观战者能看棋盘但无法落子
- 刷新页面后自动重连回原席位，棋局完整恢复
- 三种断点下无横向滚动、无元素溢出
- 聊天气泡左右方向正确、超长消息被裁剪
- 三栏底部与棋盘对齐（桌面端）
